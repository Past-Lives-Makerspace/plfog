{% comment %} The ONE Report control, rendered twice — the desktop header row and the phone's sticky bar — so the label and the modal id can never drift. Quiet by design: it is a safety valve, not a call to action. When the viewer already has an open report it renders a different thing entirely, not a disabled button and not the same button leading to a duplicate error they would only meet AFTER typing a second report. Two problems, one control. ``compact`` is the phone bar's variant and it is load-bearing, not cosmetic. .pl-wp-actionbar is a fixed, no-wrap flex row whose height is reserved by .pl-wp-has-actionbar's 5.5rem padding, and only .pl-btn children get flex:1 there. The muted "You reported this - 2 hours ago" line is an unshrinkable sentence inside a flex-wrap container, so in the bar it wrapped the cell to two lines, pushed the bar past its reserve, and a fixed element covers content with no warning. In the bar the state is therefore one 48px button; the sentence stays on the desktop control, where there is room for it and where nothing is covered. The bar's labels are also the SHORTEST that still say what they do: at 360px the four cells overflow, and a longer compact label than the desktop one it replaces would be the thing that spills. Parameters: control_id (unique per placement), compact (the phone bar), oob (the OOB swap after a report is filed). {% endcomment %}
