{% comment %} Toast notifications — fully self-contained (inline CSS + JS, no framework, no external assets). Deliberately self-contained so it cannot be broken by a stale service-worker asset cache or a missing collectstatic: the markup, styles, and logic all ship inside the HTML document, which is never cached. Class names are prefixed `plt-` so nothing else can collide with them. Include once per base template (hub/base.html, admin/base.html). Triggered by: 1. Django messages: rendered into hidden elements carrying data-toast-message / data-toast-type. Drained on load and after every htmx settle. This is the path for save -> redirect flows. 2. HTMX HX-Trigger `showToast` (via hub.toast.trigger_toast): htmx fires the kebab alias `show-toast`, caught by the window listener below. 3. Client JS: window.showToast('msg', 'success'[, 'center']) OR window.dispatchEvent(new CustomEvent('show-toast', {detail: {message, type, position}})). {% endcomment %}
