{% comment %} Body of the Put This Class On Sale modal on the Manage Class page (design spec §C.13), shared by the teach overview and the admin class detail. Rendered inline through components/modal.html's modal_body_include, so a bound, invalid form re-renders its errors inside the reopened modal. The including template sets `sale_action_url` (the teach or admin sale endpoint) before the include. sale_enabled is not a field: the buttons carry it. "Turn the Sale On" and "Save Sale Changes" post action=on; "Turn the Sale Off" posts action=off and skips validation of the amount fields entirely, so a sale can always be ended even when its stored amounts have gone stale. Every field goes through form_field.html (Rule 13). The live price line is a preview only: salePrice() mirrors ClassOffering.sale_price_cents, and the server remains the authority (the Stripe floor and free class checks live in _SaleMixin). The amount fields live in wrappers with a class, never an inline display (Rule 12). {% endcomment %}
