{% load static %} {% comment %} The five step class composer, shared by templates/classes/class_form.html (the one per-class composer) and templates/classes/admin/class_form.html (design spec §C). Built exactly like the announcement composer (templates/hub/announcement_compose.html): one page, one
, one Alpine x-data holding `phase`, x-show per step, and the .pl-phase-tabs bar. No per-step POST: every field of every step is in the DOM on every render, so one Save posts everything and the server side validation is unchanged. Context (from _composer_context in classes/views.py, plus the form context): form, formset (sessions), faq_formset, offering (may be None on create), mode (anchor_steps_json is rendered autoescaped ON PURPOSE: it sits inside the double quoted x-data attribute, so its quotes must reach the browser as " or they end the attribute.) is_admin — controls instructor / is_private / private_for_name, the discount code URL names, and the step 5 action (Publish instead of Submit for Review) composer_tabs — [{step: ComposerStep, done: bool}], the tab bar with completion marks initial_phase — the step to open on: the first broken step after a failed POST, else ?step= error_steps / error_steps_json / error_summary — the broken steps and their failing field labels anchor_steps_json — DOM id -> step number, for goToField() pipeline, readiness, is_ready — only present once the class has a pk missing_items / missing_verb — the failing readiness items behind a refused submit or publish (?missing=1 after the redirect, or the admin create preflight), rendered as the Still Missing checklist: not a form error, the form validated composer_notice — a page level refusal that is not a form error (the class was cancelled while this page was open, so nothing was saved) composer_draft_key / composer_draft_saved — the localStorage key this composer keeps its in flight typing under (per person, per portal, per class), and the one shot signal that a save just landed, so the browser copy can be dropped card_group — the genuine CatalogGroup for a saved class (None on create); the card preview frames on steps 2 and 5 render the REAL catalog card through it cancel_url, save_label `liveTitle` on the root x-data mirrors the title field as the host types, so every card frame (steps 2 and 5, and the create mode skeleton) shows the new title before the save. Each step pane carries data-composer-step="N" and the root listens for a window event composer-goto-step {step: N}: that is how anything outside Alpine (the guided tour in static/js/pl_tour.js) reveals a pane before pointing at something inside it. The reverse direction is composer-step-shown {step: N}, dispatched from the root after every phase change has painted (and once for the opening step): that is how a widget that has to measure its box (the hero cropper in static/js/hero_cropper.js) learns its pane is on screen, since a display:none pane measures as nothing. Per step validation (issue #368, item 1) lives in static/js/composer_validation.js and is called from the root: next() checks the CURRENT pane before goTo(phase + 1); saveDraft() and confirmSubmit() check every pane in order before requestSubmit() or the confirm modal, and land on the first step with a gap instead. The rules are the attributes the server rendered on the controls inside each pane (required, min, max, step, maxlength, type), read through the browser's constraint validation API, so no list of fields per step exists outside classes/composer.py. Formset rows (gallery, sessions, FAQ) carry no constraint attributes (Django builds every formset form with use_required_attribute=False), so Next never blocks on them and a half filled row stays the server's to refuse at save, on the step that owns it. Back, the tabs, goTo() and goToField() never validate: jumping around to look at things stays free. The form keeps novalidate because the browser's own bubble cannot point at a control inside a hidden pane; the step check points at the field itself. Draft persistence (issue #368, item 3c) lives in static/js/composer_draft.js: the typed text fields are mirrored into localStorage as they are typed and OFFERED back on the next load, never restored silently, because what the server rendered may be newer than what the browser kept. The notice below the tabs is the visible half of that: what is kept, when it was kept, that photos and files are not, and a way to discard it. A save clears the copy, signalled by composer_draft_saved. The step tabs ("how much of the form have I filled in?") and the review pipeline card ("where is my class with the reviewers?") are two components with two meanings (§C.4). Do not merge them. {% endcomment %}
