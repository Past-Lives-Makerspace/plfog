{% comment %} Body of the I'm Interested modal. Server-rendered inline (not fetched by HTMX), so a POST that fails validation re-renders the page with the bound form and the errors show inside the reopened modal. Every field goes through form_field.html, which wraps it in .pl-form-group; that is what styles the textarea, the select and the input from the theme input tokens (FRONTEND.md rule 13); a bare control on a hub page renders as a white box. The Alpine component follows the Best way to reach you select: `method` mirrors the select, `label()` is what the detail field's label reads (form_field.html puts it on the label through field_label_x_text), and `pick()` prefills the detail from the form's data- attributes (the member's account email, or the phone on their profile; read through $root, because $el inside a handler is the select it fired on) when the field is empty or still holds the previous prefill, so anything the member typed is never overwritten. x-init reads the select's rendered value (through the DOM: a root's x-init runs before its children register their x-ref), so a bound re-render keeps the method the member chose. {% endcomment %}
