# #502 part 4: Guild page tabs and the Reservations settings toggle

Part 4 of 4; this PR closes #502. The guild page's Orientations tab shows only when there is something to book, a Reservations tab joins it when the guild turns it on and owns a reservable item, and guild settings gains a Reservations tab with that toggle and the guild's reservable items. Mockups approved on the issue (2026-10-03): `mockups/502-orientations-reservations.html` on branch `fog/502-mockups`, views `guild-tabs` and `settings-reservations`. One amendment to the mockup: since #575 every guild settings section saves itself, so the Reservations tab has no Save button; the toggle saves on change like the Visibility toggle.

## Today

- `templates/hub/guild_detail.html`: the tablist (`x-data="{ section: 'overview' }"`, `x-init` reads `?tab=` for `meetings`, `orientations` (with `?type=` and `#guild-orientation`), `wiki`), tab buttons gated per feature, panes below. The Orientations tab renders whenever `show_orientation` (settings enabled) is true, even with zero active types; its pane includes `hub/partials/guild_orientation.html`, whose "No orientations are set up yet" branch covers the zero type case. The context is built in the guild page view in `hub/views.py` (the block starting `orientation = GuildOrientationSettings.objects.filter(guild=guild).first()`).
- `templates/hub/guild_edit.html`: the settings tabs (`section` on `plGuildAutosave`, `?tab=`), Orientations at `data-help-key="guild.run-orientations"`. The Visibility card is the single toggle pattern: a `data-autosave` form posting to `guild_visibility_save` with `components/toggle.html`, the view calling `form.is_valid(); form.save()`, `wants_autosave` → `autosave_saved()`, else a message and redirect. `GuildVisibilityForm` is the one field ModelForm.
- `Guild` (`membership/models.py`) has no reservations toggle. `Equipment.guild` has `related_name="equipment"`. Part 1's `hub/partials/equipment_cards.html` renders the card grid (locked cards included) from `cards` dicts built in `hub_equipment_index`; the index view also builds `oriented_ids, guild_ids`, the prefetches and the running orientations in one place.
- The manage page for an item is `hub_equipment_manage` (slug), gated by `can_manage_equipment`; the guild's lead and staff pass its guild tier.

## What changes

### 1. The model

`Guild.show_reservations_tab = BooleanField(default=False, help_text="Show a Reservations tab on the guild page listing this guild's reservable rooms, spaces and tools.")`. One migration (the one real DDL of the ticket; number it after the newest on main). `GuildReservationsSettingsForm(forms.ModelForm)` with that one field, label "Show a Reservations tab on the guild page".

### 2. The cards builder, shared

Extract from `hub_equipment_index` a helper `reservation_cards(request, queryset) -> list[dict]` in `hub/equipment_views.py` that does the prefetches, `_attach_running_orientations`, the member access sets, the fee lookup and the per card dicts; the index calls it with its filtered queryset and keeps its chips and search. The guild page calls it with `guild.equipment.filter(is_active=True)` (through `_equipment_queryset()` so `select_related` matches). One definition of a card.

### 3. The guild page

- `show_orientation` becomes true only when settings are enabled AND the guild has at least one active type (compute from the `orientation_types` list the view already builds; the pinned types rule from the equipment page is not needed here, a member's live booking on a retired type still shows because the Orientations tab is also gated by... keep the tab visible when the member holds a live booking or hold on any of the guild's types, so Cancel stays reachable). The `x-init` deep link branch follows the same gate (it is already inside `{% if show_orientation %}`). `guild_orientation.html`'s "No orientations are set up yet" branch stays for the live booking case only; nothing else there changes.
- A Reservations tab button directly after Orientations, rendered when `show_reservations` (`guild.show_reservations_tab` and at least one active item), with `?tab=reservations` honored in `x-init`. Its pane: a lead line "Book a tool you are trained on, or a room or space. <a href=/equipment/>All reservations</a>" and `{% include "hub/partials/equipment_cards.html" %}` with the guild's cards (`reservation_cards`), locked cards included; the `.pl-equip-grid` CSS is already there. No chips, no search on the pane.
- The guests surface (`is_guilds_surface`) shows the Reservations tab too only if the equipment index is reachable there; check `hub/urls.py`'s guest surface and, if `/equipment/` is members only, hide the tab on that surface and say so in the pane gate.

### 4. Guild settings

- A Reservations tab button directly after Orientations (`section === 'reservations'`, `?tab=reservations` already works through the `section` initializer).
- The pane, first card "Reservations": lead line "Put this guild's reservable rooms, spaces and tools on the guild page.", a `data-autosave` form (no Save button) posting to a new view `guild_reservations_settings_save` at `guilds/<int:pk>/reservations/save/` named `hub_guild_reservations_settings_save`, `@login_required @require_POST`, gated the way the other guild settings saves are for a lead or staff (the gate `guild_edit` uses; not `_require_admin`), `form.is_valid(); form.save()`, autosave branch, else message "Saved." and redirect to `?tab=reservations`. The toggle through `components/toggle.html` with description "The tab lists every active item below. A tool a member is not trained on shows locked, with a link to its orientation."
- Second card "Reservable items": lead line "Everything members can reserve from this guild. Hours, managers and photos live on each item's manage page."; `ul.pl-guild-reservables` (CSS from the mockup's first style block, lifted into `hub.css`) with one row per item of the guild, active first then by name: name, kind badge (`get_kind_display`), Active / Inactive pill (`hub-pill--ok` / `hub-pill--neutral`), and a Manage link to `hub_equipment_manage` when `can_manage_equipment(request, item)`. Empty state: "No reservable items belong to this guild yet." plus, when `can_create_equipment(request)`, "Add one on the Reservations page." linking to the add page.
- `tests/hub/_markup.py` `assert_autosave_forms_have_no_submit` already pins the no Save rule; the new form must pass it.

### 5. Closing the ticket

The PR body's Problem line reads "Closes #502, part 4 of 4". The changelog fragment is member facing (`minor`) and names the guild page tabs and the settings toggle only; parts 1 to 3 already announced theirs.
