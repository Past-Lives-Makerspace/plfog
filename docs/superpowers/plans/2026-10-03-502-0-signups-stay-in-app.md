# #502 prelude: orientation signups stay in the app, and Orientation info is rich text

Part of #502 (does not close it). Felix approved the #502 mockups on 2026-10-03 with two amendments that touch the orientation surfaces every later part builds on, so they ship first as one small PR: the external signup link goes away everywhere, and the guild wide Orientation info becomes rich text so a lead can add links there.

## Today

**External signup (#368).** `GuildOrientationSettings.external_signup_url` and `OrientationType.external_signup_url` (`membership/models.py`, with `validate_signup_url`, `ExternalSignupRequiredError` and `OrientationType.resolved_external_signup_url`) send members to an outside form instead of the booking flow. Every member road honors it: `OrientationSlot.ensure_bookable_for` raises `ExternalSignupRequiredError` unless `by_staff`; `hub/views.py` turns it into the member sentence (comment near the booking view, "An off-site-signup refusal arrives as ..."); `templates/hub/partials/guild_orientation.html` and `equipment_orientation.html` render "Sign up for this orientation" in place of the booking UI; `hub/equipment_views.py` passes `required_orientation_is_external` so `equipment_detail.html`'s banner reads "See How to Sign Up"; `membership/discord_commands.py` skips those slots in the picker and answers "takes orientation signups on their own form"; `OrientationCustomRequestForm` filters its type field to internal types and exposes `has_internal_types`, which `guild_orientation.html` checks before showing the Schedule an Orientation control. The fields are edited on `GuildOrientationSettingsForm` and `OrientationTypeForm` (`hub/forms.py`, with `EXTERNAL_SIGNUP_URL_WARNING`, the two hints and `clean_external_signup_url`) and rendered in `templates/hub/guild_edit.html` (guild wide field, the two type formset rows) and `templates/hub/equipment_manage.html` (two rows). The guild page view `select_related("guild__orientation_settings")`s the types only so the resolver does not cost a query per type.

**Orientation info.** `GuildOrientationSettings.info` is a plain `TextField` ("shown to members before they book (plain text)"), edited as a 4 row textarea on the Orientations tab of guild settings (`guild_edit.html`, `orientation_form.info`) and shown on the guild page tab as `{{ orientation.info|truncatewords:40 }}` (`guild_orientation.html`). Class descriptions, the guild emails and the help pages use the Quill editor instead: `core.widgets.RichBodyEditorWidget`, sanitized on the way in by `core.html_sanitize.clean_rich_body` (plain text stays as typed, editor HTML is sanitized), rendered by the `rich_body` filter from `core/templatetags/rich_text.py`. `guild_edit.html` already includes `_components/rich_editor_assets.html`, and since #575 `static/js/rich-editor-init.js` dispatches a bubbling `input` on every edit so the page's autosave hears it.

## What changes

### 1. Remove external signup end to end

- `membership/models.py`: drop both `external_signup_url` fields, `validate_signup_url`, `ExternalSignupRequiredError` and `resolved_external_signup_url`. In `ensure_bookable_for` remove the `by_staff` external check and its comment; keep the `by_staff` parameter only if something else reads it (grep; if nothing does, drop it and its call sites). One migration: both columns turn nullable and leave Django's state (`SeparateDatabaseAndState`), so the release still serving during the deploy keeps reading them; the real drop ships in the next migration after this release is live (STANDARDS.md section 10, add before you remove). Historical migrations that mention the field (`0172`, `0173`) are not edited.
- `hub/forms.py`: drop `EXTERNAL_SIGNUP_URL_WARNING`, `GUILD_EXTERNAL_SIGNUP_HINT`, `TYPE_EXTERNAL_SIGNUP_HINT`, `clean_external_signup_url` and the `validate_signup_url` import; remove the field from both forms' `fields`, `widgets`, `labels`, `help_texts` and the two `clean_external_signup_url` methods. `OrientationCustomRequestForm.__init__` offers every active type of the guild (one queryset, no Python filter); `has_internal_types` becomes `has_types` (true when the guild has at least one active type) and the template condition follows, with its comment rewritten.
- Templates: remove the field includes in `guild_edit.html` (three places) and `equipment_manage.html` (two). Remove the external branches in `guild_orientation.html` and `equipment_orientation.html` and their `{# External signup (issue #368) ... #}` comments. In `equipment_detail.html` the banner CTA is always "Book the Orientation"; drop `required_orientation_is_external` from `hub/equipment_views.py` and the template.
- `membership/discord_commands.py`: the picker lists every bookable slot; the "takes orientation signups on their own form" reply and its comment go.
- `hub/views.py`: rewrite the two comments that cite the resolver. Keep the `select_related("guild__orientation_settings")` only if the section builder still reads the settings row per type (check with the existing query count specs; if nothing reads it, drop it).
- `tests/membership/factories.py`: drop the field from the factories if present.
- Specs: delete `tests/hub/orientation_external_signup_spec.py`. Update `tests/membership/orientation_models_spec.py` (the `resolved_external_signup_url` describe block goes), `tests/core/events/schedule_orientation_command_spec.py` (the external cases become "every active type is offered" or go), `tests/hub/equipment_views_spec.py` (two field lists), `tests/hub/guild_autosave_spec.py` (the 422 case at the orientation settings autosave must use a field that can still be invalid, such as a non numeric `late_cancel_fee`, so the spec keeps covering the refused branch).

### 2. Orientation info is rich text

- `GuildOrientationSettings.info` keeps its column and type; its help text becomes "Orientation info shown to members before they book." (a migration for the help text only if `makemigrations` insists; it will).
- `GuildOrientationSettingsForm`: widget `RichBodyEditorWidget` for `info`, and `clean_info` returning `clean_rich_body(self.cleaned_data["info"])`, the way `classes.forms._RichDescriptionMixin` does for a description. The label stays "Orientation info". No change to the template include: `components/form_field.html` renders the widget, and the assets are already on the page.
- `guild_orientation.html`: render the whole body, `{{ orientation.info|rich_body }}` inside a `<div class="hub-text-muted pl-orientation-info">` (load `rich_text`), no truncation: this is the lead's instructions to the member, not a teaser. One CSS rule in `static/css/hub.css` next to the other orientation rules so paragraphs and lists inside it keep the muted 0.9rem size and a 0.75rem bottom margin. Any other place that prints `info` (grep `orientation_settings.info`, `settings_obj.info`, `orientation.info` across `hub`, `membership`, `templates`) renders through `rich_body` for HTML or `rich_body_to_text` for plain text (emails, Discord).
- The autosave on the Orientations tab already saves the hidden textarea on the editor's bubbling `input`; verify the orientation settings autosave spec still passes with the new widget and add one case that posts editor HTML with a link through the `X-Autosave` path and reads it back sanitized.

### 3. Nothing else moves

The Schedule an Orientation control on the guild tab keeps its label and its gate (`allow_custom_requests`, not all done, the guild has an active type). The per type `description` stays plain text. Parts 1 to 4 of #502 follow in their own PRs.

## Specs

- `tests/hub/orientation_info_rich_text_spec.py`: the Orientations tab renders the Quill mount for `info`; posting editor HTML with a link and a `<script>` stores the sanitized HTML (link kept with hardened `rel`, script gone) and the guild page tab renders the link; a plain text body saved before the editor renders as paragraphs; the autosave POST answers 200 and the stored value is sanitized.
- `tests/hub/orientation_signups_in_app_spec.py`: neither form has `external_signup_url`; a POST carrying it is ignored and saves the rest; the guild tab and the equipment page never render "Sign up for this orientation" or "See How to Sign Up"; `ensure_bookable_for` books for a member on a guild whose settings row used to carry a link (no exception class exists); the custom request form offers every active type; the slash command lists every bookable slot.
- Existing specs that render these pages keep passing: `tests/hub/guild_edit_spec.py`, `tests/hub/guild_orientation_tab_spec.py`, `tests/hub/orientation_settings_spec.py`, `tests/hub/guild_autosave_spec.py`, `tests/hub/equipment_views_spec.py`, `tests/membership/orientation_models_spec.py`, `tests/core/events/schedule_orientation_command_spec.py`, `tests/template_comment_lint_spec.py`.
- E2E: `tests/e2e/orientation_booking_spec.py` and `tests/e2e/guild_settings_autosave_spec.py` on Postgres.
