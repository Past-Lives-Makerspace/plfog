# #502 part 1: Reservations

Part 1 of 4 for #502 (does not close it; part 4 does). The Equipment directory becomes the Reservations page, spaces like the loading dock become a reservable kind, a tool the member is not trained on renders locked with a way to get trained and a way to say "I was trained before the portal", and a Space Manager capability lets a member add rooms and spaces without the site wide Equipment Administrator grant. The Permissions tab gains both toggles. Mockups approved on the issue (comment of 2026-10-03); the Reservations list and the locked card are `mockups/502-orientations-reservations.html` on branch `fog/502-mockups`, views `reservations` and `permissions`.

### 3. The locked card and the pre portal sentence

- The card carries `pl-equip-card--locked`; a `.pl-equip-card__lock` overlay with the lock glyph sits over the photo (markup lifted from the mockup, `aria-hidden="true"`).
- The badge row becomes `.pl-equip-card__state`: the "Orientation needed" badge, then a `.pl-help` bubble (FRONTEND.md rule 19, the `pl-help` pattern, never `title=`) whose icon has `aria-label="Already trained: <sentence>"` and whose bubble text is the pre portal sentence: "Trained on this before the Member Portal went live? Message us in #member-portal-general on Discord and say you need access to the <item name>."
- Under it, `<a class="pl-equip-card__cta">Book the orientation</a>` to `equipment.required_orientation.orientation_anchor_path` (the owner page's anchor today; part 2 re-points it at the type's card on the Orientations page).
- Every other state renders exactly as today. Only the Reservations page includes this partial today; part 4's guild pane will reuse it and lock the same way.

CSS in `static/css/hub.css` next to the `.pl-equip-*` rules, lifted from the mockup's first style block: `.pl-equip-card--locked .pl-equip-card__photo`, `.pl-equip-card--locked .pl-equip-card__placeholder`, `.pl-equip-card__lock`, `.pl-equip-card__lock-glyph`, `.pl-equip-card__state`, `.pl-equip-card__cta`. Tokens only, both themes.

`equipment_detail.html` banner, `needs_orientation` branch: the two leaves that start "You need the X orientation before you can book time here." (the Book button leaf and the paused leaf) gain the same pre portal sentence after it, in the same paragraph. The booked and requested leaves do not. A member in the `ok` state never sees it.

### 4. Space Manager

- `AdminCapability.Capability.SPACE_MANAGER = "space_manager", "Space Manager"` after EQUIPMENT; `DESCRIPTIONS` entry: "Adds rooms and spaces members can reserve, such as the loading dock, and manages the ones they add. Cannot add tools." Choices only migration.
- `membership/permissions.py`: new `creatable_equipment_kinds(request) -> list[str]`: every Kind for a full admin (`view_as` aware, as today) or an EQUIPMENT holder; `[ROOM, SPACE]` for a SPACE_MANAGER holder; `[]` otherwise. The capability legs read the request's actual member, like the existing gates. `can_create_equipment(request)` becomes `bool(creatable_equipment_kinds(request))`. The same pair on `Member` (`creatable_equipment_kinds()`, `can_create_equipment()`), the role twin. `can_manage_equipment` is unchanged: a Space Manager manages only what they add, through the resource tier.
- `EquipmentForm.__init__` takes `kinds: Collection[str] | None = None` (None means every kind, the manage panel's Details tab keeps passing nothing). When given, the `kind` field's choices narrow to those kinds, and `clean()` refuses a posted kind outside them with "Space Managers can add rooms and spaces. Ask an Equipment Administrator to add a tool." on the `kind` field. The restriction lives in the form, not the view.
- `hub_equipment_add`: `kinds = creatable_equipment_kinds(request)`; 403 when empty (as today for non creators); the form gets `kinds=kinds`. After `form.save()`, if `can_manage_equipment(request, equipment)` is false for the creator, create `EquipmentStaffMembership(equipment=equipment, member=<the request's member>, granted_by=<same>)` so the manage page opens for them; then redirect to the detail page as today. The Reservations page's `can_create` already reads `can_create_equipment`, so "+ Add" shows for a Space Manager.
- `MemberCapabilitiesForm`: two new toggles after `cap_refunds`, `cap_equipment` (EQUIPMENT) and `cap_space_manager` (SPACE_MANAGER), labels and help text from the model as the others; both in `_FIELD_TO_CAP`. The Permissions tab template loops the form and needs no change. The View As duties list picks the new value up from `Capability.choices`.
