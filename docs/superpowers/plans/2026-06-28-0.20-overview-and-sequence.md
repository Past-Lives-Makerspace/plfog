## Cross-cutting decisions (locked)

- **Tab architecture (item 4):** FULL inline. Orientations, Meeting Notes, and Events become `x-show` sections inside
  `guild_edit.html` driven by the same Alpine `section` state as Basic/Images/Announcements — identical structure, no
  standalone pages, tab bar always present. Per-record add/edit forms (one meeting note, one event) stay as their own
  small pages but link back to the relevant tab. The old list URLs redirect to `guild_edit?tab=…` so nothing dangles.
- **Announcement broadcast (item 3):** email + Discord stay **default ON** (opt-out). New per-announcement booleans
  let the author untick either; the emit call respects them. The audience note names "Joined" members explicitly.
- **Versioning:** this whole release is **one PR = one version**, staying at **`0.20.1`**. Each commit refines the
  curated, member-facing CHANGELOG entry at `0.20.1` (adds its bullet); invisible polish (the margin fix, the Discord
  tooling change) gets **no** changelog bullet — the git commit is the record. Because the Discord fix (item 5) makes
  the announcer post only `version == VERSION`, keeping every member-facing bullet under the single `0.20.1` entry means
  the eventual announcement carries exactly this release's features — together, once.
- **No prod data migration with backfill** in any commit; if a commit needs a schema change it must be additive. Flag
  immediately and stop if any item turns out to need a destructive/backfill migration (re-scope with Josh).
