# #502 part 2: the Orientations page

Part 2 of 4 for #502 (does not close it; part 4 does). Members get one page, `/orientations/`, listing every orientation they can sign up for, as cards that carry a photo; the staff dashboard moves under `/orientations/manage/`; Orientations joins the sidebar above Reservations with its own feature switch; an orientation type can carry its own photo, set on either editor with the same image field the guild banner uses, and falls back to its owner's image. Mockups approved on the issue (2026-10-03 comment): `mockups/502-orientations-reservations.html` on branch `fog/502-mockups`, views `orientations` and `settings`. Felix's amendments: a card with no posted times says "Schedule an Orientation" (never "None of these times work?"), and nothing on this page sends anyone to another website (the prelude PR removed external signup).

## Today

- `/orientations/` is the staff dashboard (`hub/urls.py` routes `hub_orientations_dashboard`, `hub_orientations_export`, `hub_orientation_add_member`, `hub_orientation_toggle_completed`; `hub/views.py` `orientations_dashboard`, 403 for members), linked from Admin Tools by name. Two strings pin the path: `tests/billing/refunds_service_spec.py` (`"in_app_url": "/orientations/"`) and the guided tour selector `form[action='/orientations/add-member/']` in `membership/help_content.py`.
- The per type booking UI lives twice: `templates/hub/partials/guild_orientation.html` (guild page tab) and `templates/hub/partials/equipment_orientation.html` (equipment page), both rendering the sections `hub.views._orientation_sections` builds (done / hold / booking / slots, plus the guild's blocks and custom request layered on by the guild view). Booking roads: `hub_orientation_book` (slot, confirm modal, paid types go to Stripe), `hub_orientation_block_starts` + `hub_orientation_block_book` (Pick a Time modal, htmx), `hub_guild_orientation_request_custom` (custom time), `hub_orientation_cancel_mine`, `hub_orientation_checkout_resume` / `hub_orientation_checkout_cancel_hold`. Each redirects to the owner page (`_owner_redirect` → `OrientationType.orientation_anchor_path`) or the guild page by slug.
- Photos: `Guild.banner_image` and `Equipment.photo` with `HeroCropMixin.hero_object_position`; `OrientationType` has no image. The guild banner is edited through `components/image_field.html` (`guild_edit.html`, `shape="rect"`, a delete endpoint and confirm per image). The Orientation Types formsets (`OrientationTypeForm`, rows in `guild_edit.html` under `data-formset="otypes"` and in `equipment_manage.html`) are plain fields; the guild one autosaves (#575: a file input posts on `change`, `static/js/guild_autosave.js` clones `template[data-formset-template]` with `__prefix__` replaced).
- Sidebar: `base.html` writes each entry twice (`{% active_nav %}`, `{% url %}`, `_sidebar_feature_link.html`); `core/features.py` is the registry (a key with no row reads ON). `tests/hub/nav_feature_flags_spec.py` and `tests/e2e/feature_switch_screenshots_spec.py` pin the entries.
- Part 1 left the locked Reservations card's "Book the orientation" link on `orientation_anchor_path`.

## What changes

### 1. Routes and sidebar

- Dashboard routes move under `orientations/manage/` (`manage/`, `manage/export/`, `manage/add-member/`, `manage/bookings/<pk>/toggle-completed/`), names unchanged. Update the two pinned strings. `/orientations/` becomes the member page below.
- `core/features.py`: `Feature(key="orientations", name="Orientations", off_description="Takes Orientations out of the sidebar.")` directly before the `equipment` row.
- `base.html`, both blocks: Orientations directly above Reservations, `hub_orientations` URL, icon `hub/partials/nav_icons/_orientations.html` (the graduation cap svg from the mockup, same size and stroke as the others), `help_key="nav.orientations"`.
- `tests/hub/nav_feature_flags_spec.py` gains the marker; `tests/e2e/feature_switch_screenshots_spec.py` adds `orientations` to its key tuples.

### 2. The per type photo

- `OrientationType.photo = ImageField(upload_to="orientations/photos/", blank=True, validators=[validate_image_size], help_text="Photo shown on this orientation's card. Leave empty to use the guild banner, or the equipment photo for an equipment orientation.")`. One migration (real DDL). Orphan handling as the guild banner (`delete_orphan_on_replace` in `save`, the same helper the Guild uses; and delete the file on the delete endpoint).
- `OrientationType.card_image` property: the type's own photo, else the equipment's photo for an equipment owned type, else the owning guild's banner (the equipment's guild for an equipment owned type with no photo), else `None`. `OrientationType.card_image_position`: `"50% 50%"` for an own photo, else the owner's `hero_object_position`. Callers that render many cards compute the owner position once per owner (a box crop reads the image's dimensions from storage).
- `OrientationTypeForm.Meta.fields` gains `photo`. Both editors render it with `components/image_field.html` (`shape="rect"`, `label="Photo"`, `tooltip_html="Wide photo, about 1600x900, JPG or PNG. Shown on this orientation's card. Leave empty to use the guild banner."` on the guild editor and "... to use the equipment photo." on the equipment editor, `max_bytes=settings.MAX_UPLOAD_IMAGE_BYTES` through the context, `current_image=t.instance.photo`, `delete_url` and `modal_id="delete-otype-photo-<pk>"` for a saved row, `delete_button_text="Delete photo"`, `confirm_title="Delete this photo?"`, `confirm_message="The card goes back to the guild banner. This can't be undone."`), placed after Description. The empty row template renders it too (no current image, so no delete). Verify in a browser (e2e) that a row added with "+ Add an orientation type" shows the preview after a file is chosen: the component's inline script is cloned with the row, and the `__prefix__` replacement rewrites its ids.
- New endpoint `orientations/types/<int:pk>/photo/delete/` named `hub_orientation_type_photo_delete`, `@login_required @require_POST`; gate: a guild owned type through `_require_can_manage_orientations(request, guild)`, an equipment owned one through `can_manage_equipment`; deletes the file, clears the field, redirects back to the editor tab (`?tab=orientations` on guild settings; the equipment manage page's orientation tab) with a success message. The guild editor's autosave posts the photo on change (the form is multipart already; `hub/autosave.py` `autosave_saved` rows unchanged). The equipment formset saves on its Save button as today.
- The guild page and equipment page per type sections do not show the photo; only cards do.

### 3. The page

`hub_orientations(request)` in a new module `hub/orientations_views.py` (keeps `hub/views.py` from growing; import the helpers it needs from there), URL `orientations/` named `hub_orientations`, `@login_required`. Template `templates/hub/orientations.html`: `components/page_header.html` titled "Orientations" with "Get trained on a guild or a tool before you book it."; the chip row and search from the Reservations page (`.pl-equip-filters`, chips All / Guilds / Equipment as `?owner=guild|equipment`, search `?q=` on type name, placeholder "Search orientations"); the card grid `.pl-equip-grid`; the Completed disclosure; the empty state "No orientations are open for booking right now." (and "Nothing matches those filters." with a Clear filters link when filtered). No List / Calendar tab strip yet (part 3 adds it).

**Which types.** Guild owned: `OrientationType.objects.active().filter(guild__in=Guild.objects.visible(), guild__orientation_settings__is_enabled=True)`; equipment owned: `.filter(equipment__is_active=True)`; one queryset with `select_related("guild", "guild__orientation_settings", "equipment", "equipment__guild")`, ordered by owner name then `sort_order`, `name`. Plus any inactive type the member holds a live booking or hold on (the equipment page's pinning rule, `_equipment_orientation_sections`), rendered with its state block only.

**Per type data**, built in one pass with a fixed number of queries whatever the number of types (a spec asserts the count): slots `OrientationSlot.objects.bookable().filter(orientation_type__in=types).with_seat_holding_count().select_related("orientation_type", "orienter").order_by("starts_at")`, grouped by type, each with `with_display = slot.with_label`; a closed guild (`is_closed`) contributes no slots and its types read Paused; blocks `OrientationAvailabilityBlock` upcoming for the guilds in the set, `select_related("orienter", "guild")`, filtered per type with `valid_starts_for`; then `_orientation_sections(types, member, slots_by_type, slot_cap=3)`, with `blocks` (first three) and `more_times` (true when more than three slots or blocks exist) layered on. The paid note, the hold, booking, done states and their confirm modals come from the shared partial below.

**The card** (`templates/hub/partials/orientation_card.html`, markup from the mockup): `.hub-card.pl-equip-card` with `id="orientation-type-<pk>"`; the photo strip `.pl-equip-card__photo` from `card_image` with `object-position: card_image_position` (the room placeholder glyph when none); `.pl-orient-card__owner` (guild badge linking the guild page; for an equipment type the equipment name badge linking the equipment page plus the guild name muted); `.pl-orient-card__name`; `.pl-orient-card__meta` (duration, `Free` or the price chip); then exactly one state:
- Completed: the card sits in the Completed disclosure, with "✓ You've completed this orientation." and the Recorded on line.
- Hold: the "Payment pending" badge, the sentence and Resume payment / Cancel.
- Booking: Requested or Confirmed badge, the when line with location and orienter, the awaiting or paid note, Cancel my orientation.
- Paused (closed guild, or the pinned inactive type): the Paused badge and the closed message or "This orientation is paused."
- Open: the paid note when paid; up to three `.pl-orient-card__slot` rows with "Book" (the slot confirm modals of the guild partial: paid, with orienter, without) and, under them, up to three block rows with "Pick a time" (the same `hx-get` modal as the guild page); "More times" to `orientation_anchor_path` when `more_times`; with no slot and no block, "No times are posted yet." and, when the guild allows custom requests, the **Schedule an Orientation** control (closed by default, revealing `OrientationCustomRequestForm` with the type preselected and the type field hidden, posting to `hub_guild_orientation_request_custom`). An equipment owned type with nothing posted shows only the sentence.

**Coming back.** Every booking road the page uses takes an optional `next` POST field (through `confirm_field_name="next"` on the confirm modals and a hidden input on the custom and block forms): `orientation_book`, `orientation_block_book`, `guild_orientation_request_custom`, `orientation_cancel_mine`, `orientation_checkout_cancel_hold`. A new helper `_orientation_return(request, orientation_type)` in `hub/views.py` redirects to `next` when it is a local path (`url_has_allowed_host_and_scheme`, same host, no scheme) and to the owner page otherwise; the guild and equipment pages pass nothing and behave as today. The paid checkout's Stripe return keeps landing on the owner page.

**The shared partial.** The hold and booking blocks (sentences, buttons, confirm modals, both owner wordings through `sec.type.is_equipment_owned`) move into `templates/hub/partials/_orientation_type_state.html`, included by `guild_orientation.html`, `equipment_orientation.html` and the card, so the three never drift. Confirm ids unify on one prefix per action (`cancel-orientation-hold-<pk>`, `cancel-my-orientation-<pk>`); grep `tests/` for the old `cancel-equip-` ids and update.

**The locked card.** Part 1's "Book the orientation" link now points at `OrientationType.orientations_page_path` (`reverse("hub_orientations") + "#orientation-type-<pk>"`). `orientation_anchor_path` stays for emails and the blocker banner.

CSS: lift the `.pl-orient-card__*` and `.pl-orient-done` rules from the mockup's first style block into `hub.css` next to `.pl-equip-*`.
